# 画质与性能分阶段验收

本轮任务按 P0 → P1 检查点 → P3 等价性验收推进。Hugin 先区分对齐 TIFF、焦点蒙版和 Enfuse 输出的问题；复用新的平坦区门禁必须等待 P1 检查点通过。所有真实照片结果写入 `diagnostics/white_background_20260930`，不得用于替换正式输出，诊断工具不移动原片。

> 用户后续复核发现9651–9709红色印刷表面颜色不均，原ROI没有覆盖该区域。原灰齿整体主体验收结论撤回并更正，已补充同组修复、颜色接缝/实际轮廓回归及新版灰齿三execution等价性，见下方专节。逐像素等价性不能证明共同输出没有颜色缺陷。

## 已确认的源码基线

- `merge_workers` 默认 3，配置范围 1～6；不改变配置上限。
- `minimum_stack_group_size` 默认 4；短组可以直接作为诊断输入，但不能据此更改正式流水线的最小组规则。
- Quality 全尺寸 `INTER_LANCZOS4` warp，焦点标签逐帧更新，`levels=1`、sigma1窄边界过渡。默认 cached 的 RGB 缓存有界，容量 1 GiB；仍有全尺寸浮点融合临时数组。显式 streaming 只在九像素支持带内使用浮点RGB累加。
- 中性色稳定化条件为 `gray < 235` 且通道差 `< 65`，使用 15×15 标签中值滤波。灰度 240～255 的白底不受这条规则保护。原有 `build_focus_labels` 另有背景稳定化，其效果需要单独测量。
- Hugin 已使用 `-m`、`-C` 和 `--use-given-order`，有捕获顺序/相关性/镜头参数重试；不能将“新增 -m”作为修复。
- 两条路径共用 `build_focus_labels`；旧 Hugin 蒙版启用中性物体轮廓保护，可能将整件物体锁给单帧。修复后的默认 quality 蒙版使用逐像素焦点归属和原中性色标签中值规则。Hugin 保留 hard-mask，层数按平坦表面色调漂移自动选择 1 或 5，显式配置可覆盖。

## 诊断记录

每次后端运行在组工作目录写入 `fusion_profile.json`，成功和失败都记录。包括配置快照、OpenCV 版本、物理内存、总耗时、分阶段事件、100ms 采样的进程树 RSS 峰值和读写计数。多组共用一个进程时，进程树统计包含其他组；单 worker 内存测试应在隔离子进程中执行。

Quality 记录 JPEG 顺序读取、解码、warp、焦点响应、标签正则化、融合和编码。P0 基线使用 Pillow，以防解码器变化混进算法对照；P3另验证110张正式选片解码全RGB一致，以及四组选片最终输出一致后，应用默认改用OpenCV `imdecode`。阶段时间存在嵌套和预取重叠，不能直接相加当作总耗时。

`runtime.registration_diagnostics=true` 开启全尺寸高纹理 ROI 相位相关残差测量；默认正式运行开启，直接构造后端时可显式传入。它只记录残差与置信度，不修改变换矩阵。合成按已有 `preview_transforms` 和 `analysis_shapes` 的真实坐标缩放；缺少恢复坐标时才按现有 640px 路径重建。当前正式整组选片的保存坐标为 1280px，固定探针曾使用 640px，不能把两者混为同一条正式路径。失焦、遮挡和视差可能降低相位相关置信度，不能将低置信度位移当作修正量。

Hugin 记录每次实际输入顺序、完整命令和重试参数，及 TIFF 位深、尺寸、总字节数、Enfuse 命令与 hard-mask 状态。在组工作目录放 `.keep` 可保留对齐 TIFF 和 Enfuse 焦点蒙版。`align_image_stack` 内部同时执行对齐和 TIFF 编码，外部计时无法精确拆分这两段；报告必须标注合并计时。TIFF 读取与蒙版写入有独立事件。

Hugin 工作目录优先使用可识别的 SSD：缓存本身在 SSD 上则保留原位置，否则尝试系统临时目录和程序所在盘。Windows 介质查询失败或映射不明时保持原缓存位置；日志记录路径、介质和选择原因。`runtime.hugin_temp_directory` 可显式覆盖。清理只允许删除本服务私有根目录的直属组目录，诊断 profile 仍保存到项目缓存。重试开始前释放上一轮 TIFF，`.keep` 除外，避免每次重试叠加整组 TIFF。

`runtime.hugin_alignment_preset="first"` 是显式的 `--align-to-first` 对照开关，默认仍为 `"legacy"`。它保留 `-m`、实际选片和验证阈值；当前相位残差对照尚不足以证明可全局启用。`AlignConfig.extra_args` 在重试中保留，不再被默认重试参数覆盖。

`reference_first` 另将已选中的正式 `preview_reference` 放到 Hugin 实际输入首位，并带 `--align-to-first`；其他输入保持原有相对顺序。它只改变 Hugin 自己的求解锚点，不使用 Quality 矩阵生成 TIFF。没有选中的参考帧时明确失败；alignment order 含未选中的图片时也明确失败，保证同组选片双后端对照。正式工具箱13帧A/B未显示速度收益，不作为默认。

进程 IO 计数并非物理 HDD 吞吐或 IO 等待。磁盘介质类型和物理吞吐需在测试报告中记录独立系统采样；采样不可用时明确标为未测，不以逻辑读写字节数替代。

启动与每组 profile 记录 OpenCL 的 `haveOpenCL`、`useOpenCL` 和已启用设备。检测失败继续使用 CPU。尚未实测等价性与总耗时收益的操作不得启用 UMat 加速；`INTER_LANCZOS4` 是否走 GPU也必须实测，不能从 UMat 类型推断。

## 固定输入与噪声底

固定清单需要保存每组完整路径、选片、参考帧、配准矩阵及其实际坐标尺寸、ROI 坐标，算法 A/B 使用同一清单。至少覆盖白底、黑杆/高反差、灰齿、40MP、60MP、40 张以上大组和困难位移/视差样本。新增样本追加清单版本，不覆盖已保存的基线。

实图正常验收必须先核对用户提供的 17 套拍摄边界，再使用 `GroupAnalyzer(AppConfig())` 的完整正式分析对象，包括选片索引、参考帧、变换及坐标尺寸。不能只借正式选片再手动换参考帧；源图对照使用实际锁定参考和相同几何。禁止以宽文件名区间手工构造 `selected_paths`，或以 `registration.valid` 代替景深组有效性判断。手动固定子集、重新构建参考坐标仅用于局部受控诊断，报告必须注明；跨拍摄套的输入移出正常画质验收。三张短组按正式默认 4 张规则记录 `NO_MERGE`，不为测试放宽。

本轮早期 `8835–8922` 黑杆样本跨多个拍摄套，相关增益和门禁数据只保留为混合输入的探索记录，不算真实景深组的困难样本验收。早期全 ROI 主体亮度和小瑕疵指标也不能单独证明画质：前者含纸面背景，后者主要是纸面划痕与噪点。重新固定真实主体掩膜，并增加与参考原片比较的低频斑块指标，之后重测该指标的噪声底。

正式诊断入口 `diagnostics/white_background_20260930/baseline/formal_inputs.py` 校验用户边界、现存原片、正式选片索引、完整保存的变换和参考坐标；调用后检查分析对象未被实验代码修改。历史结果保留并标明适用范围，不通过修改目录名称将手工探针变成正式证据。正式通过选片的 12 套只代表可进入合成，不能代表画质已通过。

默认全目录路径另经 `ImageScanner + StackGroupDetector(pause_seconds=20)` 验证：340 张分为 23 组，没有跨用户边界，08914–08921 和 09573–09603 各被分割。09573 与 09575 相隔 206 秒，构图差为 0.080，超过默认 0.025；默认会跳过单张 09573，另分析 09575–09603 的 29 张。先前工具箱 13 帧 A/B 使用用户完整边界的正式选片，仍可用于指定边界实验，不能代表默认自动路径。它与自动组的选片/参考坐标必须分别保存、分别验收，不从旧 13 帧矩阵删除一张后冒充新分析。

默认自动选片映射已补齐：23组中13组可合成。15个完全一致的用户边界引用既有正式分析；`09575–09603` 重新分析选中13张、参考09594，`08915–08921` 重新分析选中6张、参考08915；其余6个单张和4个三张组跳过。用户17边界/12READY与默认23组/13READY是不同输入路径，不能交换引用。完整路径集合和分析来源见 `selection_validation/默认自动路径选片映射.md/json`。

白底低频指标固定为 `Gaussian(output, sigma=7) - Gaussian(source, sigma=7)`，扣除 ROI 残差中位数，再按亮度差 4、面积至少 64 像素分别统计正负连通块。它反映来源切换造成的斑块；`image - Gaussian(image)` 的高通残差另外记录，用来观察细碎噪点，两者不能互相替代。主体 ROI 在源图上先固定，边缘统计不能把 ROI 的纸面纹理、真实双轮廓或相邻齿尖当作新增双线/晕边。无法可靠识别单一外轮廓时该指标标为不可用。

同一组选片重复运行，保存雪花小连通块数量、总面积、最大面积，以及双线得分、边缘锐度、晕边宽度。以重复测量范围确定噪声底；不得用固定百分比取代自然波动。难组失败也要保存阶段和错误，不得静默改用另一后端。

worker 1、2、3、6 对同一固定工作负载测总时间、每小时组数、组延迟、峰值内存和物理磁盘指标。若内存预算不足而限制实际并发，每次记录 requested/effective workers、可用内存、单 worker 实测峰值和限制理由。

## 算法与默认值检查点

1. 先保存旧行为基线，再单独测试全局亮度增益；记录每帧估计值、应用值、有效采样量及高光约束。
2. 启用增益实验时，增益后的帧用于焦点响应和分亮度段噪声估计。纹理统计宽高各缩小一半，像素数为原图四分之一，最大 12MP，逐帧更新；最终标签仍取自全尺寸响应。增益实验未通过主体回归，应用默认关闭。
3. 平坦且无可靠焦点证据的区域锁到参考帧；可靠边缘安全带禁止锁定，只做窄边界过渡。此时先验收，不做连通域清理。
4. 保存清理前后输出，单独检验小标签孤岛清理。正常组任何关键边缘恶化超过噪声底即不通过。
5. P1 完成后保留其整组内存参考实现，流式版须比较最大逐像素误差、MAE、PSNR 和关键 ROI。容差先定义，统计误差后才决定是否切换默认。
6. 60MP 单 worker 实测峰值用于实际并发预算。缺少高像素原始样本时，不能将低像素或放大照片的结果声明为 60MP 验收。
7. OpenCL 操作逐项测速度和一致性，只启用具有收益且通过 A/B 的环节；无可用设备时记录跳过，保留 CPU。

P5 虚拟缓存和分块处理暂不实施。新全尺寸增益、标签和平坦区结果如果未来持久化，必须将对应版本加入缓存键；当前分析焦点缓存与合成诊断文件用途不同，不能仅因日志变更使分析缓存全部失效。

应用当前默认 `runtime.quality_variant="gate"`、`quality_gate_edge_mode="localized"`、`quality_printed_edge_guard=true`、`quality_exposure_gain=false`。印字守卫经过下述补充实图回归，只用于Quality gate/clean。`gain` 单独测全局增益，`clean` 才追加小连通块清理；二者均不默认启用。正式增益A/B改变主体亮度和锐度，clean没有额外改善证据。旧legacy和v4保留为显式回退/对照；原v5的四组正式代表集P1.6检查点与新版补充回归分开记录，不引用早期手工探针。

正式v4在50帧锯片上减少了白底负斑块，整个工具箱边界仍有明显残余斑块，灰齿部分低频指标增加。v4保留为失败的A/B证据，不宣称白底修复完成。完整选片、几何和ROI可追溯报告以 `diagnostics/white_background_20260930/selection_validation/正式选片报告.md`、`baseline/P0_provenance_v2.md` 和各组正式报告为准。

## P3 候选实现与验收

`quality_execution` 提供 `cached`、`memory`、`streaming`，默认cached；`quality_jpeg_decoder`默认opencv。memory保留每张完整对齐RGB作为P1参考，实际内存不足时明确失败，不自动换算法；streaming不保留整组RGB。二者要求opencv解码。`cached/pillow`加legacy变体可复现本轮旧实现作为回退路径。

OpenCV路径整体读取JPEG后用 `imdecode(IMREAD_COLOR | IMREAD_IGNORE_ORIENTATION)` 解码并转RGB；全进程读盘信号量为1，释放后才解码。`jpeg_read_wait` 是信号量等待时间，不是操作系统I/O等待。当前110张正式选片与原Pillow解码全RGB一致；40MP/60MP尚未覆盖。

streaming第一遍参考帧先处理，不预取；最终全尺寸标签保持原始选片索引的平局规则。背景色调平局也按最小原始索引决定，避免处理顺序改变结果。第二遍按原选片顺序读取/解码/warp，复用第一遍的增益字典；不重新估计。增益仍默认关闭。参考帧诊断与增益预览复用第一遍源图，原中性色兼容掩膜在第一遍采集，不为标签正则化额外解码一次。

最终RGB使用uint8硬归属输出；sigma1的九像素支持带内才使用float32累加，权重仍来自原全尺寸Gaussian，累加顺序不变。逐行条带读取窄带累加器，避免整图RGB浮点临时副本。该阶段不改几何矩阵或焦点响应算法。

强制验收先定义标签、编码前RGB、最终JPEG全像素最大误差0、MAE0、PSNR无穷；不在看到差异后放宽容差。固定四组对cached/memory/streaming各运行一次、单worker独立进程串行，使用默认流水线实际OpenCV线程预算。保存标签和RGB诊断文件的额外IO同样记录，单次性能结果不代表冷HDD或长期稳定吞吐。默认候选要求显著降低峰值内存，且总时长增加不超过预先设定的20%；结果不达标就保留显式低内存选项。

原v5检查点的正式12个子进程全部通过输入守卫、analysis unchanged及全像素等价性，尚未启用新增印字守卫。streaming对cached在灰齿/工具箱/锯片/黑杆上的耗时变化分别为+41.16%/+55.31%/−15.47%/+74.32%，峰值RSS分别下降72.21%/54.59%/72.58%/36.23%。只有锯片满足预设20%时长条件，故不将streaming设为默认，也不据此构造未经验证的自动切换阈值。完整结果见 `diagnostics/white_background_20260930/p3/formal_ab/p3_formal_ab_report.md`；新版等价性补验见下节。

`quality_worker_peak_60mp_bytes=0` 表示尚未获得60MP单worker实测，不以29MP数据填充。只有quality streaming使用这个实测校准；可用内存减去原有安全余量后计算 `effective_workers`，每次启动记录requested/effective、可用内存、实测峰值及原因。容量不足一个worker时保持一个可取消等待的消费者，开始合成前MemoryGuard另外预留该实测峰值。配置默认3、上限6保持不变。校准只适用于已测版本及不超过60MP的输入，换版本或更大原片须重新实测。

## 红色印刷表面补充回归

用户指出9651–9709红色表面的浅红色块后，原灰齿整体主体验收撤回。新增ROI为原尺寸 `(1200,495,51,28)`、`(1121,522,84,42)`，使用实际清晰DSC09694/09695和失焦DSC09652/09653的同坐标作为控制；不把失焦的全局参考09670当作主体颜色标准。

`PrintedEdgeOwnership` 的统计尺寸宽高各半、最大12MP；彩色证据为通道差≥65且灰度≥30。填充彩色轮廓并向内收缩对应原图8px后，灰度≥140且通道差≤45的内部区域才参与印字检测；3×3开运算去掉孤立亮点。使用原全尺寸焦点响应在真实印字边界的强度，向附近原图32px支持范围传播，每帧只更新最大证据与uint16 owner。最终仅同时满足候选源帧彩色、原winner彩色及内部区域的像素改变标签，原RGB值仍从相应源帧取出，保持sigma1窄带融合。平局按最小原选片索引处理。

## 本机 OpenCL 检查结果

使用新增原始输入 `F:\测试集\DSC09575.JPG`（6224×4672，29.1MP），RTX 5060、OpenCV 5.0.0；完整记录见 `diagnostics/white_background_20260930/opencl/report.md`。resize、两种 warp、GaussianBlur、Laplacian、Sobel、焦点响应和权重在包含同步下载的测试中均比 CPU 慢；全图 RGB 浮点累加约快 3.4 倍且误差为 0，但尚不等于整条流水线有收益。

焦点响应的很小浮点误差在合成三帧诊断中导致 13 个标签像素变化，因此不能默认启用 GPU 焦点决策。Lanczos4 warp 的 UMat 输入也不证明执行了 GPU kernel。当前产品继续使用 CPU；流式窄带累加应完成后再评估 GPU 全图累加是否还有优势。40MP/60MP 原始输入的缺项已由用户确认继续，保持待验收。
