# Focus Stack Studio · Auto Focus Stacking

面向焦点堆栈摄影的 Windows 桌面工具。导入一批 JPG 照片后，自动扫描、按场景分组、选择清晰区域互补的照片，完成对齐和融合，并按组输出合成图片。

适合批量商品摄影，以及同一主体、构图基本不变但对焦顺序不固定的照片序列。组内照片不必按焦点远近排列；画面变化、主体移动或反光变化较大时，仍需检查分组和合成结果。

## 快速使用

1. 选择照片目录，或将文件夹拖入窗口。当前输入支持 `.jpg` / `.jpeg`；需要子目录时勾选“包含子文件夹（递归扫描）”。
2. 选择结果目录，留空时写入源目录内的“合成”文件夹。
3. 根据拍摄情况设置“最少相似照片数”和“分组拍摄间隔”。默认使用高质量引擎；其他引擎在“高级与性能设置”中选择。
4. 点击“开始处理”，查看组状态、进度和日志。任务结束后可筛选结果、查看合成预览、放大图片或打开文件所在位置，也可打开处理清单。

界面支持明暗主题。输出支持 JPG 和 TIFF。原图自动归档默认关闭；开启后可选择移动、复制或硬链接，请按自己的文件整理方式选择。

## 分组与选片

共同流程：**扫描排序 → 场景分组 → 预览配准与清晰覆盖选片 → 所选引擎合成 → 保存结果**。

- 有 EXIF 拍摄时间的照片优先按时间排序，其余按文件名与路径自然排序。递归扫描时，子目录照片会进入同一排序序列，子目录本身不代表分组。
- 自动分组综合相邻画面的构图、颜色、尺寸和拍摄间隔。默认分组拍摄间隔为 20 秒；达到该间隔后结合画面变化判断，默认超过 60 秒才单凭间隔强制切分。仅停拍 20 秒不一定产生新组。
- 默认最少组张数为 4，可在界面调整。组内通过预览配准和清晰区域覆盖选择互补照片，通常无需使用全部原片；选片不足或不需要融合的组会单独记录。
- 焦点远近顺序不作为分组依据；严重构图变化、主体移动、重复拍摄或缺少时间信息时，自动判断可能需要人工检查。

需要固定分组时，可在照片目录根部放置 `stack_groups.json`：

```json
{
  "groups": [
    ["IMG_0001.jpg", "IMG_0002.jpg", "IMG_0003.jpg", "IMG_0004.jpg"],
    ["IMG_0005.jpg", "IMG_0006.jpg", "IMG_0007.jpg", "IMG_0008.jpg"]
  ]
}
```

每个数组是一组。使用不重复的文件名，不填写目录路径；未列出的照片仍按连续片段自动分组。递归扫描出现重名文件时，建议拆开目录处理。显式分组仍需通过最少张数、选片和对齐检查。

## 三种合成引擎

三种引擎共用分组和选片结果。

| 引擎 | 主要流程 | 使用侧重点 |
| --- | --- | --- |
| 高质量（默认） | 复用预览变换，在全分辨率分析焦点归属，处理印字、材质色调与主体外沿，再做窄过渡融合 | 商品细节、细小印字和材质边缘 |
| Fast（C++） | 在代理图上确定主要来源，再逐帧渲染原图并执行局部边缘与接缝处理 | 减少全分辨率重复计算；仍需检查小孔、细字和外沿 |
| 实验模式（Hugin / Enfuse） | Hugin 独立对齐，程序生成焦点硬蒙版并修正边缘与色调，Enfuse 渲染 | 比较另一套对齐流程；会产生较多中间文件，画幅可能裁剪 |

高质量和 Fast 不调用 Hugin。Windows x64 原生算子支持线程预算和加载诊断；相关原生库加载失败时，可用对应 NumPy/OpenCV 实现继续处理，耗时可能增加。实验模式需要可用的 Hugin/Enfuse，便携包已内置。

没有一种引擎能保证所有场景都更快或完全消除伪影。建议先处理代表性照片组，检查外沿、反光、细小印字和不同材质交界，再运行大批量任务。

## 本版更新与验证范围

- EXE、窗口和任务栏统一使用蓝色叠层图标；透明 ICO 包含 16～256 像素共九档尺寸，适配不同显示比例。
- 更新工作台界面：明暗主题、结果筛选、图片预览与放大、进度及资源状态展示。
- 采用 C++ 选片覆盖计数、边缘支撑传播和单层 RGB 累加，并优化共享图像特征与融合缓冲的生命周期。
- 精简分析流程，减少重复计算和清单写入，完善缓存复用与恢复任务的 Hugin 排序补齐。
- 修复有效区域缩图判定，以及彩色轮廓内侧清晰细节的来源保护，改善已验收样本中的红灰交界模糊块和蓝色外沿软边。

源码采用前已有一次默认设置全流程记录：465 张原片、34 组，生成 24 张成品、10 组无需融合、0 错误；24 张成品均完整解码。采用后相关定向检查为 34 项通过。该记录对应默认高质量流程，不能代表三种引擎的完整回归，也不构成所有场景的画质或性能保证。

本次发布另检查便携程序启动、SVG 图标、EXE 内嵌的九档 ICO、应用与窗口图标、原生 DLL、内置 Hugin/Enfuse 加载及压缩包完整性；不重复执行整批照片融合。详细范围与局限见：

## 从源码运行

需要 Python 3.11 或更高版本。桌面发布目标是 Windows x64；仓库附带的 DLL 也面向该平台。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
python main.py
```

安装后也可通过 `focus-stack` 启动。主要依赖为 NumPy、OpenCV、Pillow、psutil 和 PySide6；开发依赖包含 pytest。

从源码使用实验模式时，可通过界面选择 Hugin 工具目录，或配置 `HUGIN_BIN`；程序也会查找项目运行时和系统路径中的 `align_image_stack` 与 `enfuse`。

Windows 打包配置为 `packaging/AutoStack-main.spec`，固定输出 `AutoStack-main.exe` 并嵌入 `layers.ico`。修改原 SVG 后可运行 `python tools/generate_app_icon.py` 重新生成九档尺寸。使用 PyInstaller 打包时，通过 `AUTOSTACK_HUGIN_BIN` 指向已准备好 Hugin/Enfuse 及其运行库的目录；默认查找 `.runtime-deps/hugin/bin`。

### 原生库与测试

```powershell
python build_cpp.py --compiler auto --openmp on
pytest
```

原生构建需要已有的 Windows x64 C++ 工具链，默认输出到 `build/native`，不会自动替换随项目附带的 DLL。请同步部署对应运行库、许可证和构建清单。构建、回退与线程预算详见 [原生算子说明](docs/native_kernels.md)。部分真实后端集成测试需额外环境或显式开启，以测试报告中的跳过原因与范围为准。

## 第三方工具与源码

便携包内置 Hugin 2025.0.1 的 `align_image_stack` 与 Enfuse 4.3（提交 `993fd4822e8d`），作为独立命令行程序处理图像。它们沿用上游版权及 GPL 许可证。

`LICENSES/` 保存许可证；`THIRD-PARTY-SOURCES.md` 和同一 Release 的 `Hugin-Enfuse-third-party-sources.zip` 提供对应源码、依赖源码与来源清单。转发便携包时，请保留这些资料及源码获取渠道。

## 项目结构

```text
focus_stack_app/
├── core/       扫描、分组、配准与选片
├── files/      原图归档与命名冲突处理
├── fusion/     焦点融合、原生算子与材质修正
├── hugin/      Hugin / Enfuse 集成
├── pipeline/   调度、工作线程与任务恢复
├── storage/    数据库、清单与缓存
├── ui/         PySide6 工作台与图片预览
└── utils/      图像、EXIF、日志与资源工具
tests/          自动化测试
docs/           架构、原生构建与验收记录
```

本地照片、生成结果、诊断、缓存、虚拟环境与开发运行时不随源码提交；可分发原生 DLL 和对应许可证随程序提供。
