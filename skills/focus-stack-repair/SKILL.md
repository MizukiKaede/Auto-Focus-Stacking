# Focus Stack Assistant 修复流程

目标是修复融合算法的通用原因，让后续图片受益，同时保留真实纹理、阴影、磨损、印字和物理边界。通过修改项目代码与重新融合解决问题，不用生成式图像替代真实照片。

本 skill 总结的是项目修复方法，不会自动恢复已暂停的实验。开始或续接任务时，以用户最新指令决定范围；最新历史状态见 [参考记录](references/repair-history.md)，其中版本、路径和环境均须在当前设备确认。

## 项目约束

- 本项目用户要求避免过度审查、哈希校验、无关样本、全套测试、并发组合和 GPU 测试。只运行验证当前修改所必需的定向检查及指定样本融合。
- 本项目测试由用户指定的 **gpt-6-luna、max 子 agent** 执行；给它明确的样本、实际分析、环境、隔离代码目录、测试文件和输出目录。工具或模型不可用时说明限制，不悄悄换模型。
- 用户要求复杂原因咨询时，可临时使用其指定的 **gpt-6-astra、high**。给它实际原片、对齐数据和分阶段证据，要求解释可验证的原因及具体修复；咨询不替代实图验收。普通工作不自动增加咨询代理。
- 原始照片只读。用户要求保留的版本，其代码、图片、profile 和证据全部冻结；下一版使用独立代码和新输出目录。不要仅给图片改名，实际仍导入主项目包。
- 不把图名、产品编号、指定颜色常量或人工 ROI 写成产品分支。ROI 可用于诊断、裁剪与前后比较。
- 缺失样本按用户已确认的状态记录待验收；不为补齐报告扩大范围。40MP/60MP 缺失样本属于本次历史边界，不代表所有任务都缺这些样本。

## 确认实际输入与运行环境

先定位用户指出的成品及其实际融合 profile、缓存数据库。从只读数据库和 profile 导出该输出的组号、选片索引及顺序、原片数、参考帧、完整矩阵、分析尺寸和配置，保存到诊断目录的 `provenance/`。

继续使用这份实际分析，不用旧实验清单或另一目录的同名图片代替；例如历史 09712 的 47 帧不能被旧 46 帧实验替代，目录 2 的 0522 也不能套用上一批 group36。选片或矩阵缺失时明确说明，不能默默重新分析后声称是相同输入。

确认实际应用的 Python 可执行文件、OpenCV/NumPy/Pillow、导入包路径、配置及缓存路径。普通 `python`、应用 `.venv` 和测试环境可能不同；正式融合以当前应用环境为准。不要固定使用历史 OpenCV 4.13 或 5.0，也不要设置 `PYTHONPATH=.runtime-deps` 来覆盖环境。

换设备后确认磁盘和原片映射。历史 F: 路径不表示本机存在 F:；若必须映射，核对该组原片列表和记录结构，保持选片、矩阵及参考不变，并记录映射，不做哈希。

## 用分阶段证据定位原因

先在同输入、同环境下复现问题。按症状选择必要的捕获内容：原始焦点赢家、对齐 RGB、实际源帧、各后处理前后标签、融合前后 RGB、校正场及 profile。优先复用已有捕获，不重复执行整组融合来取同一证据。

对用户指出的完整色带、纸面、边界或齿条检查，再用代表位置解释机制。对可疑点追踪最终来源、清楚的候选来源、原位清晰度、RGB 和标签被哪个阶段改写。区分以下原因：

| 症状 | 优先检查 |
|---|---|
| 雪花或长条色块 | 帧间低频偏差、同材质采样支持、密度和幅度的硬阈值 |
| 白字周围浅色晕边 | 是否借用失焦源、种子纯度、连续覆盖被颜色掩码截断、纹理误保护 |
| 灰齿或外沿变软 | 彩色边缘来源是否与相邻灰色实物处于不同焦平面、传播后目标位置清晰度 |
| 内部纹理被抹平 | 纹理或低彩度装饰是否被当成白墨、背景或外沿 |

用户确认焦点连续推进时，把它作为输入条件；仍需检查局部赢家和后处理，不能据此假定所有相邻材质同焦。没有直接证据时把原因标为推断，避免先归咎对齐。

## 修改通用规则并隔离候选

依据证据做最小相关修改。焦点标签、颜色补偿和边缘来源是不同机制，避免用统一增益或整图平滑掩盖错误来源。

颜色修复优先比较参考与源在**相同坐标、共同纯材质支持**上的低频差分。分别平滑两侧不同采样区域再相减，可能把真实阴影变成色差。保留细纹理、自然照明、材质边界；稀疏支持和较大偏差使用连续权重及保护，不无依据扩大校正。当前实现及失败教训见 [参考记录中的机制说明](references/repair-history.md#可复用的机制教训)。

边缘归属用颜色识别可靠物理种子，用清晰度给来源排名，再按实际需要传播。排名与覆盖可信度分开，避免缩放清晰度后误关停覆盖。传播时检查相邻材质自己的局部细节，不因为边缘清楚就把邻近区域全部交给同一帧。打印覆盖的处理顺序和纹理统计的净距也可能导致伪晕边。

预览从原始焦点赢家或该候选应有的阶段状态开始，不能在旧错误标签上继续叠加修补。明确轻量预览、局部 probe 与完整正式融合的区别。`final` 等目录名不是通过凭据。

每版写独立版本号，记录包来源和算法路由，保存候选配置、输出与失败结论。用户要求“保留当前版”时，先保存完整代码/测试/runner 和产物，再在隔离副本中修改；检查实际导入路径，防止候选互相污染。

## 定向检查与完整实图回归

定向单元检查验证行为，例如相同输入 RGB 不变、偏差收敛且细纹理保留、真实阴影不被抹平、材质边界保护、稀疏支持连续衰减、独立焦平面的细节保留、处理顺序和错误种子排除。只增加能验证本次缺陷的检查。

使用实际选片和矩阵，串行重新融合用户指定图片。历史可比配置为 Quality `cached`、`gate/localized`、printed guard 开启、候选 surface tone 开启、全局 gain 关闭、OpenCV threads=3、JPEG100/4:4:4；先核对用户这次输出的实际配置，不把历史参数强加到别的任务。

看完整图片，并对完整问题区域做同坐标原尺寸比较；同时检查邻接白字、真实齿形、金/蓝纹理、纸面划痕及阴影。指定的回归样本必须同时检查。单元通过、几处来源正确、改写像素数或一个小框改善都不能代替实图验收。

**任一指定样本新增明显退化，就否决整版。** 保留失败证据，说明改善和失败分别在哪。不要以局部收益抵消另一图片的纹理损失；不要将“未见明显退化”写成像素完全不变或所有未来样本已通过。

## 交付、报告与停止条件

只有本轮指定实图与必要回归通过后，才考虑采用候选、启用默认。若任务包含默认配置修改，确认空配置、缺键旧配置以及应用服务到后端的实际传递；源码确认不等于已打包程序生效。

只有在用户授权的交付范围内替换成品，先备份旧成品，再复制通过验收的新结果；原片不动。用户仅要查看或保留候选时，只交付候选链接，不覆盖成品。

报告以最终行为和限制为主，列出实际输入/环境、相关原因、候选结果、定向检查、完整实图比较和交付状态。修改此前不准确的完成结论，明确失败目录与通过目录。左右比较注明版本和顺序；运行耗时仅作为当次记录。

用户要求“测完本版先暂停”时，完成该版测试、对照报告和证据整理后停止，不再运行下一版。若当前请求只是整理 skill 或报告，不恢复融合试验。没有全部通过时保留候选或标记失败；暂停也不等于完成修复。
